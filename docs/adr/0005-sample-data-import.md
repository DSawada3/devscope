# 0005: 明示操作によるサンプルデータの一括追加

- 日付: 2026-10-25
- 状態: 採用

## 背景・受入条件

デスクトップ版は保存済みデータを使うため、ブラウザー用サンプルが自動表示されない。デバッグ用の読み込みボタンを控えめな位置に置き、デスクトップでも画面を確認できるようにする。
受入条件は、明示的なボタン操作、表示中の週への追加、既存データの維持、同一内容の重複回避、関連するタスク・カテゴリの補完、保存失敗時の全件保全、再起動後の復元とする。

## 選択肢

- 初回起動時に自動投入する：利用者のデータにサンプルが意図せず混ざる。
- 一時的なデモモードへ切り替える：保存データとの切り替え・編集中の状態を別途設計する必要がある。
- 既存の作成 API を順番に呼ぶ：途中失敗で一部だけ追加される。
- 一括追加 API を明示操作で呼ぶ：既存データを維持し、保存を1回で確定できる。

## 決定と理由

カレンダー下部のステータス付近に、小さな「サンプルデータを読み込む」ボタンを置く。サイドバーを閉じていても使える。製品の表示確認にも使うため、Vite の開発モードだけには限定しない。初期読み込み成功後だけ有効化し、保存中は連続操作を止める。

既存の `demoBlockTemplates` を正本とし、`createDemoBlocks(now, weekDate)` で表示中の週の予定と、現在時刻までに終了した実績を生成する。日付の生成・実績の判定は端末のローカル時間を使い、未来の実績を作らない。成功時は予定の週表示へ切り替え、カテゴリの絞り込みを解除して追加結果が見えるようにする。

Rust に `import_sample_data({ blocks: BlockInput[] })` を追加する。入力は1〜64件に制限し、全入力を検証してから既存 JSON を読み、カテゴリ・タスク・ブロックをまとめて1回保存する。既存のロックと一時ファイル置換を共用し、失敗時は既存ファイルとストアを維持する。新しいファイル形式・依存・権限は導入しない。

カテゴリは初期4件の ID を受け付ける。不足している初期カテゴリは補い、同名の登録済みカテゴリがあればそれを利用する。タスクは作業名・カテゴリ・プロジェクト・工程が等しい場合は追加しない。ブロックは ID を除く全項目が等しい場合は追加しない。再度読み込んだ時点で終了済みになった実績は追加される。既存サンプルを編集した場合、その元の内容を再読み込みすると別件として追加される。削除済みのサンプルも再追加できる。

戻り値は確定済みのブロック・タスク・カテゴリ・工程・プロジェクト一覧と追加ブロック件数とし、Zustand に一度で反映する。サンプルのプロジェクト候補は既存の履歴補完規則で返す。ブラウザー版も同じボタンを使い、メモリ内のコピーを組み立ててから確定する。

## 影響と検証

デスクトップで追加したサンプルは通常のデータとして保存・編集・削除できる。読み込みボタンは既存の実データを消さない。初回起動時は引き続き空のカレンダーとする。
Rust テストで一括保存・再起動後の復元・重複回避・カテゴリ補完・既存データ保全・不正入力・保存失敗時の全件保全を確認する。Chrome テストで表示週・モード・絞り込みの反映、未来の実績の除外、再試行と復元を確認する。実際の WebView2 / IPC 操作は別途検証する。
