# 設計判断の記録（ADR）

重要な設計判断は、実装に先立って、または同じ変更内で `NNNN-short-title.md` に記録する。
番号は既存の最大番号の次を使い、初回は `0001` とする。本文は原則日本語で記述する。
既存の構成説明は [全体設計](../../ARCHITECTURE.md) と [フロントエンド設計](../architecture/frontend.md) を参照し、過去の判断理由を推測して ADR にしない。

対象例は永続化方式、共有状態の所有者、日時モデル、Rust / UI の責務・権限、主要な依存技術の採用・置換。
局所的な修正すべてに ADR は不要。判断を変更するときは新しい ADR から旧 ADR を参照し、旧記録を「置換済み」にする。

以下をコピーして使用する。

```markdown
# NNNN: 判断の題名

- 日付: YYYY-MM-DD
- 状態: 提案 / 採用 / 却下 / 置換済み

## 背景・制約

解決したい問題、現状の制約、受入条件。

## 選択肢

既存方式を維持する案を含め、比較した案と利点・欠点。

## 決定と理由

選択した方式と、他の案より適している理由。

## 影響と検証

責務・データ・互換性・依存ライセンスへの影響、移行方法、検証方法と残課題。

## 関連資料

設計資料、開発計画、根拠、関連 ADR へのリンク。
```
