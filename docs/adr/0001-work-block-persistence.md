# 0001: 作業ブロックを Rust コマンド経由で JSON に保存する

- 日付: 2026-10-18
- 状態: 採用

## 背景・制約

作業ブロックの CRUD をアプリ終了後も保持する。画面は Zustand を確定済みデータの正本とし、FullCalendar に重複保存しない。
受入条件は、再起動後の復元、期間に重なる予定・実績の取得、不正入力の拒否、保存失敗時の既存ファイル・入力の保全。

## 選択肢

- メモリのみ：既存方式だが再起動後の復元を満たさない。
- localStorage：ブラウザーでは簡単だが、ネイティブ側での保存・検証の責務が定まらない。
- SQLite：大規模データ・検索に適するが、依存とマイグレーションの設計が増える。
- Rust + JSON：現在の小規模な作業データを追加の DB 依存なしで保存できる。毎回ファイル全体を読み書きする制約がある。

## 決定と理由

Rust に4つの Tauri コマンドを追加し、アプリデータディレクトリの `work-blocks.json` に保存する。
パス指定を UI から受け取らず、汎用的なファイル操作権限は公開しない。ローカルのアプリ画面から呼び出し、リモート URL の capability は設定しない。
Tauri の `withGlobalTauri` を利用して npm 依存の追加を避ける。JSON 用の serde / serde_json は既存ロック済みの推移的依存を直接依存にする。

プロセス内は Mutex、プロセス間は同ディレクトリの `work-blocks.json.lock` の OS ロックで読み書きを排他する。
標準のファイルロックを使うため Rust 1.89 以降を必要とする。競合時は `BUSY` を返し、ロック用ファイルは残すがハンドルの解放・プロセス終了でロック自体は解除される。
一時ファイルに書き込み・同期してから置換する。破損・未知バージョンは自動初期化せずエラーにする。
停電に対する完全な耐久性・バックアップ・外部によるファイル編集・ネットワーク共有上での動作は保証しない。

日時は既存の端末ローカルの暦日時 `YYYY-MM-DDTHH:mm` を維持し、UTC 変換や Asia/Tokyo 固定を行わない。
この段階ではタイムゾーンを持たないローカル予定表として保存し、端末のタイムゾーンを変えても保存された時分は変えない。
夏時間の曖昧な時刻・存在しないローカル時刻を識別するモデルは未導入。バックエンドは暦日・時分・大小関係を検証する。
共有・端末間同期・実経過時間の厳密な比較を導入する前に別 ADR で見直す。

画面は起動時に全件読み込み、保存成功の戻り値だけを Zustand に反映する。表示期間とカテゴリの絞り込み・集計は従来どおり派生値として計算する。
読み込み中・失敗時と保存中は編集を止める。保存失敗時はフォームを保持し、ドラッグは戻す。
ブラウザー版には Rust がないためサンプルをメモリ上で提供する。デスクトップの障害をブラウザー用データにフォールバックして隠さない。
デスクトップ初回は空の一覧にし、サンプルは自動投入しない。

## 影響と検証

ID はバックエンドで永続カウンターから採番する不透明な文字列とする。ブラウザーのデモは従来どおり UUID を使う。
複数プロセスのファイル破損・読み書き競合は防ぐが、画面間のリアルタイム同期や同一項目の楽観的ロックは実装しない。併用時は最後の更新が優先され、別画面の変更を見るには再読み込みが必要。
入力検証・ファイル復元・更新失敗・排他を Rust テストで、UI の API 接続と再試行を Playwright の通信モックで検証する。
実際の Tauri / WebView2 操作は別の確認が必要。依存条件は [依存・素材記録](../provenance.md) に記録する。
