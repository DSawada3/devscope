# 0003: タスクから利用する開発工程・プロジェクトの登録

- 日付: 2026-10-25
- 状態: 採用

## 背景・制約

タスク登録画面から開発工程とプロジェクトを登録する画面へ移動し、戻って選択できるようにする。
受入条件は、両画面への導線・登録と一覧・タスク入力の維持・登録値の選択・端末保存と復元・旧データの保全・失敗時の入力保持と再試行とする。

## 選択肢

- 固定カテゴリを開発工程として可変にする：色分け、絞り込み、開発時間の集計と API 列挙値に影響する。
- 開発工程を独立した任意項目にする：既存カテゴリの意味と履歴を保ち、要件定義・実装・テストなどを自由に登録できる。
- ID 参照と更新・削除を含むマスターを導入する：柔軟だが名称変更時の履歴や削除制約の仕様が必要になる。

## 決定と理由

開発工程は既存の作業カテゴリと独立した `phase` とする。TaskInput / WorkBlock に任意の文字列を追加し、タスク選択時に他の作業内容とともにコピーする。旧データ・省略入力は空文字として読み込む。既存のカテゴリによる色分け・絞り込み・時間集計を維持する。

開発工程とプロジェクトは名前を値とする一意の候補一覧とし、ID は導入しない。登録時は trim 後1〜60 UTF-16コード単位、同一一覧内の重複は拒否する。別一覧で同名は許可する。更新・削除は今回実装しない。タスクのプロジェクトと開発工程は任意選択とし、ブロックの値は履歴のコピーであるため、API では登録一覧への外部参照制約を課さない。

Rust の既存 BlockStore に `list_development_phases` / `create_development_phase` / `list_projects` / `create_project` を追加する。既存 JSON の version 1 に `developmentPhases` / `projects` を追加し、省略時は空配列とする。読み込みでは名前・文字数・重複を検証する。ロック・一時ファイル保存・保存成功後の確定を共用し、追加権限は不要。古いアプリによる再保存は追加項目を失うため、ダウングレードには対応しない。

一覧取得では保存済みタスク・ブロックの名称を trim・重複除去して候補末尾に補う。旧プロジェクト名も選択でき、既存データは読み込み時に書き換えない。候補が履歴由来でも重複登録を拒否する。

確定した候補は既存 Zustand が所有する。TaskManager のローカル状態で登録画面を切り替え、タスクフォームは非表示で保持する。RegistryManager は新しい名前とエラーをローカルで持ち、保存成功時に選択値を TaskManager へ返す。画面から戻ったときは直近の登録値を選択済みにする。キャンセル相当の戻る操作では一覧を変更しない。新規依存は追加しない。

## 影響と検証

起動時はブロック・タスク・両候補一覧を取得し、すべて成功するまで編集を止める。ブラウザー版はメモリ上の候補を使い、再読み込みで追加値が失われる。
Rust テストで保存・復元、旧 JSON と旧名称の取得、文字数境界・空白・重複、不正保存データ、保存失敗時のファイル保全を検証する。Chrome テストで両画面への遷移、タスク入力保持、登録値の反映、予定へのコピー、失敗時の再試行と復元を確認する。実際の WebView2 / IPC 操作は別途確認する。
