# 0002: タスク登録と時間ブロックへの選択入力

- 日付: 2026-10-25
- 状態: 採用

## 背景・制約

利用者は事前に決めた作業をカレンダーへ割り当てる。毎回タイトルを入力する方式から、別画面で登録したタスクを選ぶ方式へ変更する。
受入条件は、タスクの登録・一覧・選択、カテゴリとプロジェクトの初期反映、入力途中の日時・メモの維持、端末での保存・復元、旧作業ブロックの編集互換性、保存失敗時の入力保全とする。

## 選択肢

- 自由入力を維持する：改修は少ないが、事前登録した作業から選択できない。
- 過去の時間ブロックを候補にする：日時未定のタスクを独立して登録できない。
- 日時を持たないタスクを登録し、選択時に作業内容をコピーする：既存ブロックの保存契約を維持できる。
- タスク ID をブロックの必須外部参照にする：対応付けを強められるが、旧データ移行や名称変更・削除時の履歴規則が必要になる。

## 決定と理由

`TaskInput = { title, category, project }`、`Task = TaskInput & { id }` を追加する。予定・実績の双方から選択でき、作業名・カテゴリ・プロジェクトをブロックへコピーする。日時とメモは時間ブロック固有とする。カテゴリ・プロジェクトは選択後に調整できる。
タスクへの外部参照は持たず、既存の時間ブロックを履歴として保つ。旧ブロックは「現在の作業」を選択状態としてそのまま編集でき、自動的にタスクへ変換しない。タスクの変更・削除や予定と実績の対応付けは今回の範囲に含めない。

タスクの確定値は既存の Zustand に保持し、保存前の登録内容は TaskManager のローカル状態とする。App は画面の切り替えと入力途中の draft を管理する。ルーターや新規依存は導入しない。

Rust の `BlockStore` に取得・登録コマンドを追加し、既存 JSON の `tasks` と `nextTaskId` に保存する。ロック・一時ファイル・保存成功後の確定を共用し、新しいファイル権限は追加しない。version 1 の追加項目として読み込み、旧ファイルではそれぞれ空配列と1を補う。古いアプリで再保存すると追加項目を失うため、ダウングレードには非対応。

## 影響と検証

初回のデスクトップではタスクも空。ブラウザーは既存サンプルから重複しないタスク候補を生成し、登録内容は再読み込みで失われる。起動時はブロックとタスクの両方を取得し、片方でも失敗した場合は編集を止めて再試行を提供する。
Rust テストで旧 JSON の読み込み、タスク保存・復元、入力検証、保存失敗時の既存ファイル保全を確認する。Chrome の UI テストで登録・選択・日時メモの維持・空状態・不正入力・失敗と再試行・再読み込み・旧ブロック編集を確認する。実機の WebView2 操作は別途必要。
