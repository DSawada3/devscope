# 0006: カレンダー内の予定・実績比較と時間差分集計

- 日付: 2026-10-25
- 状態: 採用

## 背景・受入条件

予定と実績を目視で見比べ、日・週単位でタスク・プロジェクト・工程の時間差異を確認する。インサイトの画面ではなく、既存カレンダーの表示として提供する。予定と実績の個別の対応付けは行わない。
受入条件は、各日の予定と実績の並列表示、共通の時間軸・日付移動・カテゴリ絞り込み、日／週切り替え、期間内の予定時間・実績時間・差分と3軸の内訳、日またぎ・片側のみの作業・未指定項目・空期間の表示、閲覧専用、既存編集操作の維持とする。

## 選択肢

- 予定と実績の週カレンダーを左右に置く：既存部品を使えるが、同じ日の列が離れ、スクロール同期が必要になる。
- 既存時間グリッドに混在表示する：実装は少ないが、予定と実績が見分けづらくなる。
- 各日の中で予定・実績を隣接させ、1つのスクロール領域にする：同じ時刻の差を目視しやすく、同期のずれが起きない。

## 決定と理由

表示状態の型に `CalendarMode = Mode | 'compare'` を追加する。保存されるブロックの `Mode` は `plan | actual` を維持する。比較の表示モードは既存の共有 Zustand が持ち、保存形式・Rust API・権限は変更しない。

App の予定／実績切り替えに「比較」を追加する。ComparisonView で各日の予定・実績を隣接する2列に配置し、共通の時間軸とスクロール領域を使う。日表示は2列、週表示は月〜日の14列。狭い画面では比較カレンダーの内部だけ横スクロールし、日付見出しと時刻軸を固定する。同じモードの重なるブロックは横分割し、日またぎは各日の範囲に分けて描画する。

既存 FullCalendar は通常の予定・実績の編集を引き続き担当する。比較は閲覧専用なので、CSS Grid による時間軸を描画し、新しいカレンダー依存を導入しない。比較内では追加・編集・移動・リサイズを提供せず、通常表示へ切り替えて編集する。日付見出しから比較の日表示へ移動できる。

集計は Zustand のブロックから毎回導出し、ストア・ファイルへ重複保存しない。カテゴリ絞り込みは両モードに適用する。日時の計算は `dates.ts` に集約し、表示期間と重なる部分だけを加算する。開始を含み終了を含まない期間と、端末のローカル時間を維持する。同時刻の複数ブロックは作業ごとに加算する。

時間差は `実績 − 予定`。タスクは trim 済みの同名、プロジェクト・工程は trim 済みの名前でまとめ、空文字は「未指定」とする。予定だけ・実績だけの項目も表示する。個別の予定・実績の対応付け、未着手の判定、時間差の良し悪しの評価は行わない。同名タスクが別プロジェクトでもタスク軸では合算する。識別方法の拡張は将来検討とする。

ComparisonView の集計軸は表示中だけ保持するローカル状態。日付・表示形式・カテゴリは既存ストアを共用する。通常表示へ戻った際の入力、サンプル読み込みや保存データは既存規則を維持する。

## 影響と検証

外部依存・素材・保存形式の変更なし。実績比較の自動対応付けは未実装のままとする。夏時間など、既存のローカル暦日時で区別できない時刻の拡張は今回の対象外。
日付テストで期間境界・日またぎ・不正日時・差分符号・片側のみの作業・同名合算・未指定・重複配置を検証する。画面テストで日週の連動、フィルター、閲覧専用、通常表示への復帰、集計軸と表示値、空状態、狭い画面の表示と実行時エラーを検証する。Chrome の成功を WebView2 の実機確認とは扱わない。
